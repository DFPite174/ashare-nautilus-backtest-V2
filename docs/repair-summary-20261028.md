## 项目现在的定位

这是一个**基于官方NautilusTrader Python包与其原生核心的A股账户级回测引擎**，不是整个投研平台，也不是“纯Rust主程序”。Python策略通过已结束Bar及只读账户状态生成OrderIntent；NautilusTrader执行原生订单与撮合，A股适配负责制度、资金、库存、费用与公司行为，结果由参考账本和独立验收核对。

已验证的主要链路包括：日线/分钟线、多日持有、下一Bar执行、共享现金、多证券策略、T+1、委托预留与取消释放、部分成交和参与率预算、保守涨跌停限制、税前现金分红，以及受控样本中的送转与新增股冻结。

本轮可以关闭上轮5个已复现失败项；**限定场景的回测正确性门槛已通过，不能提升为全历史A股制度完整认证。** 适合下一步在明确输入契约下使用常规策略做研究回测，而不应继续以界面展示或单纯增加测试数量代替验证。

## 保留的边界与建议

1. 独立场景S39仍为NOT_COVERED：引擎不检查全天分钟序列是否齐全，接入层必须校验日历、分钟缺口、停牌和数据来源。它不再是本轮未修复的5项失败之一，但确实是使用条件。
2. Bar模型不是盘口队列、集合竞价或真实冲击模型。下一开盘IOC及整根Bar参与率预算是研究近似，不是实盘成交保证。
3. 真实回放规模有限，未完成全市场多年分钟或20人持续并发验收；当前内存物化与历史保留方式仍需按实际服务器规模评估。
4. 未覆盖全部历史制度、真实退市/停牌/送转样本、个人差别化股息税、融资融券、配股及其他资产。拆股桥仍绑定Windows/Python3.12/NT1.231.0，不能任意升级依赖沿用结论。
5. Tushare当前历史响应不等于严格历史版本PIT。样本主动选择，不能用于证明选股有效性、无幸存者偏差或稳定收益。

下一步建议先保持当前引擎接口与版本，选定一两个实际研究策略，使用固定真实数据快照保存逐笔成交、拒单、费用及每日账户结果。平台建设时再将已验证的数据规范化和回测入口作为后端任务接入；当前无需增加实盘连接或网页功能。

## 本地复验

在仓库目录及已安装依赖的环境中运行：

```powershell
py -3.12 -m pytest -q tests/test_acceptance_repairs.py
py -3.12 -m pytest -q
```

当前执行环境因系统临时目录权限问题使用工作区内basetemp，并为现有pytest环境补充已有pygments依赖路径；实际命令和日志保存在工作区outputs。这不是干净环境安装认证。测试依赖正常的环境可直接使用上面的命令。

注意选择Python3.12或已激活的对应虚拟环境，不能依赖本机默认python版本。按代码审查技能执行的独立只读复核未发现必须修复的新增回归，复核者另行运行新增13项测试通过；它不代替本报告中的全套及真实数据复验。
